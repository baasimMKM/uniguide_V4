# Premium UI/UX Design Rulebook

Apple-inspired • Minimal • Human-centered • Modern • Production-ready

මේක ඕනෑම Mobile App, Web App, SaaS Dashboard, Desktop Application, E-commerce Platform හෝ වෙනත් Digital Product එකක් Apple-level premium, clean, intuitive, minimal, user-friendly විදිහට design කරන්න පාවිච්චි කරන්න පුළුවන් complete practical design rulebook එකක්.

මේකේ ප්‍රධාන අරමුණ ලස්සන UI එකක් විතරක් හදන එක නෙවෙයි. AI-generated template එකක් වගේ නොපෙනෙන, professional designer කෙනෙක් අතින් හදපු බවක් දැනෙන, ඇත්තටම භාවිතයට පහසු interface එකක් නිර්මාණය කරන එක.

## 1. Core design philosophy

Clarity over decoration

User ට ඉක්මනින් තේරුම් ගන්න බැරි ලස්සන interface එකක් successful design එකක් නෙවෙයි.

Function over visual effects

Animations, glass effects, gradients හැම එකක්ම usability improve කරන්න ඕනේ.

Consistency over novelty

හැම screen එකකම user අලුතින් interface එක ඉගෙනගන්න අවශ්‍ය නොවිය යුතුයි.

Content over containers

අනවශ්‍ය cards, boxes, borders නැතුව content එකට ප්‍රමුඛතාව දෙන්න.

Purposeful minimalism

Minimal කියන්නේ features අඩු කරන එක නෙවෙයි. අවශ්‍ය දේ පහසුවෙන් සොයාගන්න පුළුවන් කරන එක.

## 2. Visual design system

මේ values Apple එකේ අනිවාර්ය specifications නෙවෙයි. Premium app එකක් පටන් ගන්න හොඳ practical design tokens.

| Element            | Recommended baseline                       |
| ------------------ | ------------------------------------------ |
| Spacing system     | 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 px     |
| Main page padding  | Mobile: 16–24 px, Desktop: 24–48 px        |
| Content max width  | 1100–1280 px for general layouts           |
| Body font size     | 16–17 px                                   |
| Secondary text     | 13–15 px                                   |
| Card radius        | 12–20 px                                   |
| Button height      | 44–52 px                                   |
| Input height       | 44–52 px                                   |
| Border width       | 1 px, subtle                               |
| Animation duration | Usually 150–300 ms                         |
| Accent colors      | One primary, semantic colors as needed     |
| Icon style         | Consistent stroke, size and optical weight |

### Color rules

Light mode

Quiet surfaces, high-contrast content

Dark mode

Layered dark surfaces, restrained accents

- Use neutral backgrounds; avoid heavily saturated entire screens.
- Accent color එක primary actions, active states, important highlights වලට reserve කරන්න.
- Semantic colors: green = success, red = error/destructive, amber = caution. Color alone එකෙන් status convey කරන්න එපා.
- Pure black සහ pure white පාවිච්චි කරන්න පුළුවන්, නමුත් every screen එකට අවශ්‍ය නෑ.
- Dark mode එක light mode එක invert කිරීමක් විතරක් නොවිය යුතුයි.
- Unnecessary gradients, glowing borders සහ random colorful cards eliminate කරන්න.

### Typography rules

Typography එක premium quality එකට විශාල බලපෑමක් කරනවා.

- iOS/macOS වලට San Francisco; web සඳහා Inter හෝ system font stacks.
- Maximum 2 font families; සාමාන්‍යයෙන් එකක් ප්‍රමාණවත්.
- Consistent type scale: 12, 14, 16, 20, 24, 32, 40 px.
- Body text සඳහා 1.45–1.65 line-height එකක් හොඳ starting range එකක්.
- Headings සඳහා 600–700 font weight; body 400–500.
- Heading, section title, caption, metadata වෙනස් මට්ටම්වලින් පෙන්වන්න.
- All-caps, excessively bold, gradient text සහ over-tracked letters අවම කරන්න.
- Paragraph එකකට words ගොඩක් දාලා පුරවන්න එපා; scan කරන්න පහසු කරන්න.

## 3. Layout, hierarchy and spacing

Golden rule: User screen එක open කරපු පළමු තත්පර කිහිපය තුළ තේරෙන්න ඕනේ තමන් කොහෙද ඉන්නේ, මොනවද වැදගත්, ඊළඟට කරන්න ඕනේ මොකක්ද කියලා.

1. Screen එකකට clear primary objective එකක් තියෙන්න ඕනේ.
2. Strong visual hierarchy එකක් තිබිය යුතුයි: title → important information → primary action → supporting actions.
3. Related elements එකිනෙකට ලං කරලා, unrelated sections අතර වැඩි spacing දෙන්න.
4. 8-point spacing system එකක් base කරගෙන, fine adjustments සඳහා 4 px පාවිච්චි කරන්න.
5. Every element එක coherent grid එකකට align කරන්න.
6. Cards භාවිත කරන්න content එකට genuine grouping එකක් අවශ්‍ය වෙලාවට විතරයි.
7. Whitespace deliberate විදිහට පාවිච්චි කරන්න; empty space automatically wasted space නෙවෙයි.
8. Page margins, content widths, section spacing predictable කරන්න.
9. Content-first layouts තෝරන්න; decorative sidebars සහ panels වලින් interface එක පුරවන්න එපා.
10. Desktop සහ mobile layouts දෙකම independent විදිහට optimize කරන්න.

## 5. Navigation and information architecture

Navigation එක user කෙනෙක්ට හිතන්න සිද්ධ නොවෙන තරමට intuitive විය යුතුයි.

- Primary navigation options කිහිපයකට සීමා කරන්න; mobile tab bar සඳහා 3–5 frequently used destinations හොඳ starting point එකක්.
- Mobile වල bottom tabs, desktop වල sidebar/top navigation — product එකේ complexity එකට අනුව තෝරන්න.
- Navigation labels clear කරන්න: Home, Projects, Activity, Settings.
- හැම screen එකකම current location එක පැහැදිලි කරන්න.
- Back navigation predictable කරන්න; user ගේ context, scroll position සහ unsaved work රැකගන්න.
- Common tasks සඳහා unnecessary steps අඩු කරන්න.
- Search, filters සහ sorting එකට එක වෙනුවට එකක් ලෙස භාවිත කරන්න එපා.
- Advanced options progressive disclosure මඟින් අවශ්‍ය වෙලාවට පමණක් පෙන්වන්න.
- Important actions hidden gestures හෝ unexplained icons තුළ පමණක් තබන්න එපා.

Interaction rules:

- One clearly identifiable primary action per task area.
- Secondary actions visually quieter than primary actions.
- Disabled actions should be understandable; explain unmet requirements where useful.
- Every action needs a response: loading, success, error or navigation.
- Loading states should preserve the screen structure where practical.
- Destructive actions need appropriate confirmation or undo.
- Inputs must have persistent labels; placeholder text alone isn't enough.
- Inline field validation should be specific and helpful.
- Preserve entered data if a request fails.
- Never use fake buttons, decorative controls or dead-end UI.

## 7. Motion and microinteractions

High-end UI එකක animation එක noticeable වීමට වඩා natural වීම වැදගත්.

| Interaction        | Starting guideline        |
| ------------------ | ------------------------- |
| Button feedback    | 100–180 ms                |
| Hover transition   | 120–200 ms                |
| Menu/popover entry | 150–250 ms                |
| Modal appearance   | 200–300 ms                |
| Page transition    | 200–350 ms                |
| Loading feedback   | Immediate acknowledgement |

මේ numbers design recommendations මිස fixed platform requirements නෙවෙයි.

- Use subtle opacity, scale and position transitions.
- Prefer natural easing or appropriately damped spring motion.
- Avoid layout jumps, bouncing everything, excessive parallax and continuous motion.
- Support Reduce Motion preferences.
- Animation එක user ගේ mental model එක strengthen කරන්න ඕනේ; speed slow කරන්න නෙවෙයි.

## 9. Accessibility — non-negotiable

Premium design එක visually perfect වුණත් accessibility නැති නම් ඒක complete නෑ.

- Normal text contrast අවම 4.5:1; large text අවම 3:1.
- Important UI boundaries සහ state indicators සඳහා අවශ්‍ය තැන්වල 3:1 non-text contrast.
- Touch targets comfortably sized කරන්න: iOS වල 44 × 44 pt default control size එකක් ලෙස Apple දක්වයි. Smaller platform minimums තිබුණත් practical designs සඳහා මේ ප්‍රමාණය හොඳ target එකක්.
- Keyboard navigation සහ visible focus states support කරන්න.
- Screen readers සඳහා accessible names සහ meaningful descriptions දෙන්න.
- Dynamic Type, zoom, text enlargement, reduced motion support කරන්න.
- Errors color alone එකෙන් communicate කරන්න එපා.
- Icons meaning එක තේරෙන්නේ නැත්නම් text labels දෙන්න.

W3C WCAG 2.2 AA තුළ pointer target size සඳහා 24 × 24 CSS px minimum rule එකක් ඇත, exceptions සමඟ; comfortable mobile design සඳහා සාමාන්‍යයෙන් ඊට වඩා විශාල targets තෝරාගැනීම සුදුසුයි.&#x20;

## 10. Responsive and adaptive design

- Mobile first කියන්නේ desktop එක ignore කරන එක නෙවෙයි.
- Content එකට අවශ්‍ය වෙලාවට layout breakpoints තෝරන්න.
- iPhone, Android, tablet, laptop සහ wide displays වල test කරන්න.
- Mobile වල tables වෙනුවට compact rows, cards හෝ meaningful horizontal scrolling යොදාගන්න.
- Safe areas, keyboard overlap සහ device orientation handle කරන්න.
- Hover-only actions mobile experience එකේ critical නොවිය යුතුයි.
- Desktop වල keyboard shortcuts, contextual menus සහ efficient multi-column layouts support කරන්න.
- Platform conventions ගරු කරන්න; iOS, Android සහ web තුනම එකම exact interface එක විය යුතු නැහැ.

## 11. UX writing and content design

Robot-like wording නැති කරන්න නම් microcopy එකත් design කරන්න ඕනේ.

| Avoid                                      | Better                    |
| ------------------------------------------ | ------------------------- |
| Initiate creation process                  | Create project            |
| Your operation was unsuccessful            | Couldn't save changes     |
| Click here to proceed                      | Continue                  |
| No data available at this time             | No projects yet           |
| Leverage powerful capabilities             | Choose the tools you need |
| Are you sure you wish to execute deletion? | Delete this project?      |

Good UX writing rules: short, specific, human, context-aware, truthful, respectful සහ action-oriented. Users ට unnecessarily congratulations, exclamation marks හෝ marketing hype පෙන්වන්න එපා.

## 13. Performance and implementation rules

Premium feel එක animations වලින් විතරක් ලැබෙන්නේ නැහැ. Responsiveness, reliability සහ perceived speed ඉතා වැදගත්.

- Reusable design tokens, components සහ variants පාවිච්චි කරන්න.

# MASTER UI/UX DESIGN DIRECTIVE

**Role:** Act as a world-class Senior Product Designer, Apple Human Interface Guidelines specialist, UX Architect, Design Systems Engineer, and expert Frontend Engineer.

Design and implement a premium, sophisticated, minimal, human-centered digital interface for:

**Product:** [PRODUCT NAME AND DESCRIPTION]

**Platform:** [iOS / Android / Web / Desktop / Responsive]

**Target Users:** [USER GROUP]

**Primary Tasks:** [MAIN USER GOALS]

## 1. Design Philosophy

Create an experience that feels thoughtfully designed by an exceptional human product design team, not generated from a generic AI template.

Emphasize:

- Clarity over decoration.
- Purpose over visual trends.
- Content over containers.
- Function over visual effects.
- Consistency over novelty.
- Simplicity without sacrificing capabilities.
- Accessibility, trust, responsiveness, and craftsmanship.

Follow relevant Apple Human Interface Guidelines and established platform conventions, while maintaining a distinct product identity. Do not blindly copy Apple interfaces or branding.

## 2. Visual Direction

Use a restrained, modern, refined visual language with excellent alignment, balanced whitespace, clear visual hierarchy, elegant typography, and subtle depth.

Avoid:

- Generic AI dashboard aesthetics.
- Excessive purple/blue gradients.
- Unnecessary cards and nested containers.
- Glowing borders, neon shadows, or gratuitous glass effects.
- Random illustrations, sparkles, robots, and decorative icons.
- Oversized headings without functional justification.
- Excessive rounded corners everywhere.
- Loud colors, clutter, and repeated CTAs.
- Generic marketing language and filler content.

Every visible element must have a clear purpose.

## 3. Design System

Build a consistent, reusable design system.

Recommended starting tokens:

- Spacing: 4, 8, 12, 16, 24, 32, 48, 64.
- Typography: system-native typography or an appropriate refined sans-serif.
- Body text: approximately 16 px, with comfortable line height.
- Buttons: approximately 44–52 px high.
- Card radius: approximately 12–20 px where appropriate.
- Borders: subtle, generally 1 px.
- Shadows: restrained, only when supporting hierarchy.
- Colors: neutral foundation, one primary accent, semantic feedback colors.
- Motion: subtle, responsive, purposeful.

Adapt these values to the actual platform, context, and content.

Support light and dark themes with appropriate contrast and semantic color roles.

## 4. Information Architecture

Before creating the visual interface:

1. Identify the primary user goals.
2. Define the most important tasks.
3. Establish the information hierarchy.
4. Choose a navigation structure appropriate for the platform.
5. Minimize unnecessary steps.
6. Keep important actions discoverable.
7. Preserve navigation context.
8. Use progressive disclosure for advanced features.

Prioritize fast task completion over visual spectacle.

## 5. Components and Interaction

Build clear, predictable, reusable components.

Every interactive component must have appropriate:

- Default, hover, focus, active, and disabled states.
- Loading, success, and failure feedback.
- Keyboard and touch support.
- Accessible names and focus indicators.
- Appropriate hit areas.
- Responsive behavior.

Use clear primary and secondary button hierarchy.

Forms require persistent labels, validation, helpful errors, appropriate keyboard types, and preservation of user input.

Use confirmation or undo for destructive actions.

Never create decorative elements that appear interactive but do nothing.

## 6. Motion and Depth

Use subtle microinteractions and natural transitions.

Motion should clarify state changes and preserve spatial continuity.

Avoid unnecessary bounces, delays, parallax, excessive transforms, and continuous animations.

Respect reduced-motion settings.

Use blur, translucency, and glass-like materials only where they improve separation between content, navigation, and controls.

## 7. Content and Microcopy

Write like a thoughtful human product designer.

Use concise, specific, professional, friendly language.

Avoid robotic expressions, inflated marketing claims, repetitive instructions, meaningless enthusiasm, and generic AI-sounding copy.

Prefer straightforward labels like:

- Create project
- Save changes
- View details
- Try again
- No projects yet

Never introduce fictional statistics, testimonials, or misleading data as real content.

## 8. Accessibility

Target WCAG 2.2 AA for web experiences.

Support:

- Sufficient contrast.
- Keyboard navigation.
- Semantic structure.
- Screen readers.
- Comfortable touch targets.
- Visible focus states.
- Zoom and dynamic text scaling.
- Reduced motion.
- Meaningful alternatives to color-only indicators.

Ensure accessibility is embedded in the design system, not added after implementation.

## 9. Responsiveness

Design deliberately for mobile, tablet, desktop, and different interaction modes when applicable.

Respect safe areas, viewport constraints, touch interactions, keyboard navigation, and content density.

Adapt information architecture and component layouts to the device rather than merely shrinking desktop interfaces.

## 10. Performance and Engineering

Use maintainable, production-quality components and established frameworks appropriate to the project.

Prefer reusable design tokens, semantic markup, predictable state management, optimized rendering, and minimal dependencies.

Avoid unnecessary animations, large assets, layout shifts, and performance-heavy visual effects.

Handle errors, empty states, slow networks, offline conditions, and long content.

## 11. Quality Assurance

Evaluate every screen against:

- Immediate clarity.
- Task completion efficiency.
- Visual consistency.
- Readability.
- Accessibility.
- Responsive adaptation.
- Content accuracy.
- State completeness.
- Interaction feedback.
- Technical feasibility.
- Distinctive but restrained product identity.

Remove unnecessary elements before adding new ones.

## 12. Final Quality Standard

The final result should feel:

**Premium, precise, effortless, trustworthy, elegant, human, distinctive, mature, and genuinely useful.**

It should resemble the quality of a carefully crafted, production-ready product, not a generic design-system demo, superficial concept mockup, or AI-generated landing page.

If a design decision does not improve usability, clarity, accessibility, meaningful brand expression, or functionality, reconsider it.

**The objective is not to make the interface look expensive. The objective is to make the experience feel exceptionally well designed.**
