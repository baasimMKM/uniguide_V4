# Implementation rules

- Audience is Sri Lankan post-A/L students across all fields, not only IT.
- Write meaningful Jac graph, planner and client code. Measure >=80% Jac without filler or generated/dependency inflation.
- Pin Jac 0.16.7, Python 3.12 and byLLM 0.6.19. Use their actual guides and diagnostics.
- Server only: keys, provider calls, catalogue loading, requirements, cost, route ranking and stress recomputation. No client-side substitute engine.
- Preserve pass/fail/unknown. Programme listing, admission, fees, progression, recognition and intake are separate claims.
- Models may choose supported actions/IDs, never create institutional facts or override hard gates.
- Display operational decisions, source evidence and explicit fallback; never fabricate private reasoning or successful provider/deployment calls.
- Keep student data request-local; no shared mutable evaluation boards. Bound graph/model work and validate requests.
- Use the supplied premium UI rulebook and skill. Handle labels, keyboard, focus, contrast, themes, responsive layouts and every important state.
- Reproduce defects, fix the responsible boundary, rerun focused checks and affected regressions, then update the task evidence.
- No secrets, caches, generated bundles or arbitrary reference dumps in Git. No force-push or backdating. Verify locally before JacHammer deployment.
